| Fixer assemblies load into the default `AssemblyLoadContext`, so their files stay mapped for the life of the process and `clean` can meet one | `cleanup fix=…`, `clean` | **Largely closed by I52** — a project's own analyzer/fixer assemblies are now mapped from a shadow copy in a user-private cache, so the file in `bin/` is free; what remains is that the *copies* stay mapped for the process lifetime, which no longer blocks any build. **The collectible-ALC route was attempted in 0.15.0 and reverted.** Loading them through a collectible `AssemblyLoadContext` broke fixer discovery — `CodeFixServiceTests.Cleanup_WithAnalyzerFixes_AppliesTheAnalyzerCodeFix` went red because the exports stopped resolving across the context boundary. Shipping a broken `cleanup fix=analyzers` to close a row is strictly worse than the symptom. The stale-provider and unbounded-growth halves *are* fixed: the cache key carries each analyzer's `(path, last write, length)`, it is bounded at 32 entries, and `unload_workspace` clears it. Reopen only with a loader that shares Roslyn's own types. |
| An analyzer or source generator **rebuilt while the server is running** is still served from the assembly loaded first | every semantic tool | **Not fixable in the default `AssemblyLoadContext`.** The shadow copy is content-addressed, so a rebuild does produce a fresh directory, but `LoadFromAssemblyPath` cannot load a second assembly with the same identity into the same context — it throws `FileLoadException`, and `ShadowCopyAnalyzerLoader.Map` then returns the already-loaded instance rather than losing the analyzer. Identical behaviour to before I52 (the old loader returned the cached assembly for the same path), so this is not a regression — but I52 makes it *quieter*, because the rebuild now succeeds instead of failing `MSB3027`. Plan TC7 is therefore **NOT DONE** and cannot pass without either a collectible load context (refuted in 0.15.0 — it broke MEF fixer discovery) or the child-process design (plan option E). Remedy for a user: restart the server after rebuilding an analyzer. |
| Shadow copies are reclaimed only by the seven-day startup sweep | every semantic tool | The plan's Step 6 also called for disposing copies on `unload_workspace`; that was dropped when the loader became a process-wide singleton, because two workspaces referencing the same analyzer share one content-addressed copy and a per-workspace delete would pull the directory out from under the other. Measured on this machine: 17 directories / 34 MB after roughly an hour of running this repo's own suites, because every rebuild of the fixture generator mints a new content hash. Bounded in practice by the sweep; revisit with a size cap evicting oldest-first, the way `FixerCatalog` is bounded at 32 entries. |
| A generic `detail=` verbosity knob for every listing tool | all listings | **Rejected.** `signatures`, `ids`, `containers` and `filter` already give per-tool control with names that say what they do; a generic `detail` would duplicate them and make each tool's cheapest form less discoverable. The repo rule is that improving an existing parameter beats adding a surface. `verbose` on `build`/`run_tests`/`format` is not this — it is a per-tool escape hatch from a *cheaper default*, not a knob you must find before the tool is useful. |
